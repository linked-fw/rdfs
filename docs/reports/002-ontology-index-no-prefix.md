# 002 — Ontology index; no prefix registered

## PR

### Summary

The package moves to core's ontology module layout and registers no prefix: an app lists the
prefixes it uses in its own prefix map.

- `src/ontologies/rdf.ts`, `src/ontologies/rdfs.ts`: regenerated by `linked generate-ontology`; each term is `export const X = {id: '<full IRI>'}`, the module imports nothing.
- `src/ontologies/index.ts` (generated): registers rdf (22), rdfs (15) with `registerOntologies([...], import.meta.url)`: name, namespace, terms, data files, suggested prefix. The entry and `src/shapes/index.ts` import it.
- Removed: `rdf.data.ts`, `rdf.register.ts`, `rdfs.data.ts`, `rdfs.register.ts` (`ns`, `dataFiles`, `loadData`, `_ontologyResource`, and the prefix they added). `src/package.ts` exports `registerOntologies` instead of `linkedOntology`.
- `Class.ontology` (without `rdfs:isDefinedBy`) falls back to the namespace of the app's prefix map its IRI starts with; doc comment names `Prefix.findMatch(cls.id, map)` for another map.
- `test/app-prefix-map.test.mjs` (new): with an empty map the fallback finds nothing; with `Prefix.load({rdfs})` it finds the namespace; `isDefinedBy` still wins.
- `test/shape-check.test.mjs` imports `ontologies/index.js` (own and dependencies') instead of the `.register.js` modules.
- README: the module paragraph describes the index, terms as literals, no prefix registered, and core's `createNameSpace` for a namespace function.
- Changeset `.changeset/ontology-index-no-prefix.md` (major), beside the pending patch from the vann step.
